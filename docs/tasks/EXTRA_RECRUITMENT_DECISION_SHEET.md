### 1. データモデル設計

#### Q1-1: エキストラ専用項目の保存方法
エキストラ募集で必要な項目（集合場所、開催日程、想定人数など）をどう保存するか？

**選択肢A: JSONB方式（柔軟・シンプル）**
```sql
ALTER TABLE auditions ADD COLUMN extra_details JSONB;
-- 例: {"meeting_place": "渋谷スタジオ", "event_dates": ["2025-02-15", "2025-02-16"], "expected_headcount": 20}
```
- ✅ メリット: 実装が早い、将来の項目追加が容易、マイグレーション不要
- ❌ デメリット: 日程での検索が遅い、型安全性が低い

**選択肢B: 専用カラム方式（厳密・検索最適化）**
```sql
ALTER TABLE auditions 
  ADD COLUMN meeting_place TEXT,
  ADD COLUMN expected_headcount INTEGER;

CREATE TABLE audition_event_dates (
  id UUID PRIMARY KEY,
  audition_id UUID REFERENCES auditions(id),
  event_date DATE NOT NULL,
  start_time TIME,
  end_time TIME
);
```
- ✅ メリット: 型安全、日程検索が高速、バリデーションが厳密
- ❌ デメリット: 実装コストが高い、将来の変更でマイグレーション必要
