## ⚠️ 実装時の絶対原則（必読）

### 📝 TODO.mdは常に最新に保つ

**作業開始時・完了時に必ず更新**:
- 作業開始時: TODO.mdで現在のタスク状況を確認
- 作業中: 進捗に応じてステータスを更新
- 作業完了時: 完了タスクをマーク、新たな課題があれば追記
- 重要な決定事項・変更内容を記録

**TODO.mdは開発の羅針盤** - 常に最新状態を維持することで、チーム全体の認識を統一します。

### 🎯 設計三原則を常に意識せよ

1. **[SF] Simple First - シンプルファースト**
   - 最もシンプルな実装を選択する
   - 複雑な抽象化は避ける
   - 「動く最小限のコード」を書く

2. **[DRY] Don't Repeat Yourself - 重複排除**
   - 同じロジックを2回書いたら即リファクタリング
   - 3行以上の重複コードは関数化
   - コピペ厳禁

3. **[CA] Clean Architecture - クリーンアーキテクチャ**
   - 機能ごとに1つのディレクトリに集約
   - ファイルを散らばらせない
   - `features/points/` 配下に全て収める

### 💡 実装チェックリスト

**コード書く前に自問せよ**:
- □ これは最もシンプルな方法か？
- □ 既存のコードを再利用できないか？
- □ ファイルは正しいディレクトリに配置されているか？

**コミット前に確認せよ**:
- □ 重複コードはないか？
- □ console.log は削除したか？
- □ 型定義は共通化されているか？
- □ DB更新は `make migrate` を使用したか？（`make db-apply` 単独実行禁止）
- □ 既存ファイルとの関係性を確認したか？（重複機能・競合の有無）

### 🗄️ DB更新の厳格運用

**絶対に守ること**:
1. `make db-new` でマイグレーション生成（手書き禁止）
2. `make migrate` で適用 + 整合性チェック（自動）
3. 不一致時は `make db-sync` → `make migrate`
4. Git コミット時に pre-commit hook が自動チェック

**詳細**: [DATABASE_MANAGEMENT.md](../DATABASE_MANAGEMENT.md)

### 📁 ディレクトリ構成の原則

**機能は1箇所に集約**:
- ✅ `features/points/` - ポイント機能の全ファイル
- ✅ `features/audition-types/` - オーディション種別の全ファイル
- ❌ ファイルを複数ディレクトリに分散させない

**既存ファイルとの関係性**:
- 新規実装前に類似機能の有無を確認
- 重複ロジックは既存コードを再利用
- 型定義は `packages/shared/src/types/` で共通化

### ❓ ヘルプ・ツールチップの追加

**フォームやUIにヘルプを追加する場合**:
- `HelpHint` コンポーネントを使用（統一UI）
- 配置方法・アクセシビリティ対応済み
- モバイルでもタップしやすい設計

**詳細**: [ui/help-hint.md](../ui/help-hint.md)
